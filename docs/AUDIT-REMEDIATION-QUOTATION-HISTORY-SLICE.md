# QUO-010 — Preserve historical commercial quotation state

Author / Builder: **Shashi**. Date: **2026-10-07**. Local candidate **1.102.59**, base `ff148ba62ec710a622d9b1af7e8f511b7e0b7385`. Quotation schema **2.5.3**, lifecycle receipt **1.1.0**; core **1.3.9**, routing **1.0.1** and physical quotation columns unchanged.

## Finding and preservation policy

The October 6 audit found that the automatic lifecycle phase made every quotation Draft, cleared accepted revision pointers and shared/accepted/rejected dates, removed current finalization dates and changed prior commercial revisions to Superseded. The new native baseline regression reproduced that loss before this fix. The immutable audit documents are unchanged.

Keep original commercial state in its existing canonical fields. The mapping is identity: no status, accepted/current pointer, event date, finalization date, number, customer snapshot, revision content, milestone or monetary field is rewritten by the lifecycle phase. Shared, Accepted, Rejected, Cancelled/Canceled, Finalized and unknown historical labels remain stored exactly. No duplicate archive or guessed reconstruction is necessary for values that are still present. Existing backups provide a recovery copy of the same original fields.

`normalize_revision_lifecycle()` retains its compatibility callback name but now verifies quotation current/accepted pointer bindings and revision quote/source bindings. Missing or cross-quote nonzero pointers, orphan revisions and self-referencing sources fail completion rather than being mapped to an arbitrary revision. Zero pointers on an empty draft shell are not invented by this phase. The earlier supported legacy-import repair can still complete an unfinished noncommercial draft; it refuses pointer guessing whenever existing commercial status, acceptance/date metadata, history or non-draft revisions are present. Quotation/history rows are never deleted or replaced by this validation phase.

The lifecycle receipt changes from 1.0.0 to 1.1.0, with schema completion 2.5.3. A previous completed receipt cannot bypass the new checks. The existing schema lock, InnoDB/physical checks, phase transaction, recovery/session fencing and checked marker/commit machinery remain in force. Verification or receipt failure leaves pending completion and retains the complete historical aggregate; a second run converges. Independent and interrupted installers do not rewrite data. DDL remains independently durable.

## Read-only boundary and ordinary drafts

`IDLM_Quotation_Policy::is_editable_draft()` is shared by save, autosave, discard, editor entry and edit-link rendering. It requires a correctly bound current Draft quote/revision with no current finalization date, accepted pointer or shared/accepted/rejected date. The repository additionally checks any commercial/unknown status-history transition or non-Draft/Superseded revision on that quotation. Failed evidence reads are read-only. These checks supplement existing nonce, capability and live owner/manager authorization; administrator privileges do not permit reopening history.

This also protects some previously normalized Drafts when commercial evidence survives in history or another revision. A Superseded prior revision finalized by the current ordinary draft workflow is not alone evidence of customer acceptance; repeated ordinary Draft revisions remain editable. Saves create the next Draft and finalize their source as Superseded without changing its content or totals. Mutations recheck policy after locking the quote. Actual independent HTTP workers finalizing a quote while stale save/autosave/discard requests wait before locking cannot change its durable state.

Historical detail and exact-revision CSV remain available to authorized readers, with the editor unavailable. Existing print/PDF/XLSX readers continue to use persisted revisions; this slice makes no new historical currency, terms, paper or PDF qualification claim. There is no new commercial transition or historical-to-Draft conversion action. Any requested reopening needs a separately reviewed operation that retains the original record and commercial state.

## Old lead-field import and recovery

A legacy lead with a known true `quote_shared` flag imports as Shared for the new quote/revision rather than editable Draft. Its total remains the old value. Unknown original shared/finalization/acceptance dates remain null; import history explicitly says dates and acceptance are not inferred. Lead fields and historical file reference are retained. This affects only an incomplete/missing legacy aggregate; valid existing canonical aggregates are skipped.

Complete 2.5.2 backup manifests are accepted alongside 2.5.0/2.5.1 compatibility. Columns are unchanged from 2.5.2; new round trips retain statuses, dates, pointers, content, milestones and history exactly. Existing migration receipts are excluded from backup settings and are not used as restored evidence. Actual multipart restores and repeated native restore/installation preserve the historical aggregate.

An earlier destructive migration may already have erased exact pointers/dates/states. This change does not reconstruct those values from history, totals, current lead fields or catalogue. Remaining commercial evidence prevents editing where it can be identified; a record with all evidence already lost cannot be automatically distinguished from an ordinary draft. Use an independent pre-migration backup/customer record and a reviewed repair to recover such data. These limitations are not silently labelled as successful reconstruction.

The new future schema/lifecycle receipts make an unsafe older installer incompatible. Replacing the plugin ZIP alone is not a supported downgrade. Recovery requires matching plugin/database backups and rehearsal; no old unsafe plugin was booted against these preserved customer states. Identity preservation plus successful old-backup restore is not a production rollback attestation.
