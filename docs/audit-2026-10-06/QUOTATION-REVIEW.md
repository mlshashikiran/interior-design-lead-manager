## State, schema, money and concurrency

Relationships: `leads.id → quotes.lead_id → revisions.quote_id → sections/items/milestones.revision_id`; history belongs to quote and optional revision; items carry an optional catalogue ID but all display/rate/category/unit/wood fields are snapshots. User IDs are historical metadata; current lead assignment is the detail/export authorization owner. No FKs enforce any of these relationships. Quote number and save keys unique, `(quote_id, revision_number)` unique, sequence `(type,year)` unique. Lead ID is **not** unique in quotes; one-per-lead is enforced only by the creation workflow's advisory lock. Catalogue code/category/unit name unique.

Current allowed application lifecycle: new shell/current revision Draft R01; each saved edit creates R+1 Draft and marks former current Superseded. Existing source must be current and both quote/revision Draft, rechecked after quote row lock. There is no current Shared/Accepted/Rejected/Cancelled transition action. Legacy normalization explicitly changes existing commercial states and clears acceptance pointers/timestamps (QUO-010). Payment milestones table exists and participates in backup/deletion, but current save/render uses global payment_structure instead of persisting revision milestones.

Calculations: per-item subtotal = rounded quantity × rounded rate; both positive width/height replace manual quantity with rounded area. Optional/header rows excluded. Wood discount ≤100% only affects wooden subtotal. Soft close uses configured percent on wood after discount. Additional fixed discount capped at total. GST always18%, divided CGST/SGST, IGST/design fee zero. Grand total rounds to whole currency units, including currencies selected through settings. Currency does not select tax jurisdiction. This is an INR/GST business rule exposed alongside multiple display currencies; international financial suitability has not been demonstrated.

Number reservation commits independently **before** quote-save transaction, so failed saves can leave legitimate gaps. First number in a new year relies on unique sequence key; simultaneous missing-row reservations can return retryable failure rather than retry internally. Save idempotency lookup occurs before locks and again within existing-quote transaction. Save UUID invalid/missing is replaced, so invalid UUID repeated submissions are not idempotent by key. Two stale editors saving the same current revision serialize: later one sees a changed pointer and should fail; real concurrent draft-revision save test is NOT RUN here. Autosaves have no per-request sequence/CAS token, and late autosave can leave a transient for a superseded revision; it remains inaccessible but lasts up to seven days.

Transaction safety assumes transactional storage. Aggregate save failure checks are generally explicit, but first-create error exits do not consistently release the advisory lock; MySQL normally releases connection locks on connection close, while persistent connection behavior is NOT RUN. Read errors are often treated as missing/empty data. Lead value projection directly updates lead quote_value/updated_at inside quote transaction, then invalidates cache and logs quotation activity after commit; it intentionally does not run canonical lead lifecycle hooks/conversions. Activity-log failure does not undo a committed quotation.

## Findings register

### QUO-001 — P1: new quotation accepts an existing revision without binding authorization

**Source:** `class-quotation-controller.php` L15–24, L76–98, L123–168; repository L203–205, L245–270. **Trigger/users:** signed-in quotation creator with access to a lead without an existing quotation; request carries a nonzero existing revision ID. **Expected:** new creation always inserts its own revision; incoming revision ID ignored/rejected, and all existing revision access verified. **Actual:** new branch retains posted revision_id; existing-quote validation only runs in the else branch. It later updates the supplied revision into the new quote and replaces its contents. **Impact:** another lead's historical quote content can be changed, old current pointer becomes cross-quote, and new current pointer may be absent. No existing draft-edit/revision permission is required for create branch. **Recorded evidence:** QUO-S09 synthetic handler run: revision50 moved quote99→100, original quote99 retains pointer50; shell100 has no current pointer. **Tests catch?** Existing cross-quote bundle test only rejects reading already mismatched bundles; it does not validate new save. **Remediation:** bind IDs before any persistence; new branch must reject/reset revision IDs and always insert revision. Existing branch must authenticate source relationship under lock. Add isolated real transaction regression covering ordinary create, nonzero/new IDs, cross-lead/cross-quote IDs, permissions and rollback. **Confidence:** high, handler executed with current source/test doubles; real DB/HTTP exploitability not separately exercised.

### QUO-002 — P1: quotation lists disclose data after lead reassignment

**Source:** controller L323–335; renderer L161–187; repository L663–671, L721–729; policy L44–49 and lead read-model L20–21; quote initial owner controller L86. **Trigger/users:** reassignment after quote creation, or restricted role override on a manager. **Expected:** list and direct access share current lead scope; former owner loses access, new owner discovers quote. **Actual:** list filters stored owner_user_id and does not add current lead scope. It returns live name/phone/email/project, grand total and shell metadata despite direct access denial; new owner not listed. Manager “assigned” override still passes manage-all predicate and can receive unscoped list. **Evidence:** QUO-S02 recorded SQL + current policy denial; source SELECT includes PII. **Tests catch?** Scoped list test asserts owner SQL but no ownership-change behavior. **Remediation:** apply the canonical lead read scope in joined list/count queries, and preserve metadata owner as attribution only.
