Proposed changes

  1. Sticky search row. Search and Filters (with active count) stick under the 52px top bar. Title, More and Add lead scroll away, so only one row stays pinned.
  2. One count row. The attention pills and the summary strip merge into one scrolling row of 44px filter-count pills, attention first (STD-CRM-1). Same buttons, same aria-pressed filters. About 150px less before the first lead.
  3. Card order: name, contact, status, owner, act. Name and age on top, phone and project or location on one muted line, flags (New WhatsApp, Awaiting 5h, Routing exception) as text badges.
  4. Stage and quality side by side with an 11px label above, each still a toned, editable dropdown drawn as a 32px, 14px-text pill with a 44px invisible tap area (STD-CRM-6, STD-CRM-11). The quality dropdown shows Qualified, Unqualified or Pending; plan received or pending moves to the meta line, so long values never truncate on a 375px screen.
  5. Owner, budget and tasks always visible in one meta line. Overdue tasks in red text, Unassigned in amber text. No coloured card edges (STD-VIS-3).
  6. One-tap Call and WhatsApp as 44px buttons. Call uses the existing tel: link; WhatsApp is new. The chevron moves into the action row and keeps .idlm-lead-row-expand; Show details reveals channel, studio and dates as a short list.
  7. Selection. 44px checkbox target in each card's corner; selected cards get the action border. An "All" checkbox (select this page) leads the result line on phones, lined up with the card checkboxes, because the header checkbox is hidden there today.
  8. Bulk bar at the bottom. Count and Clear on row one, action and Apply on row two. Sticky to the bottom for thumb reach, with matching list padding so the last card stays reachable (STD-LAY-5). Delete still confirms via IDLMDialog with the count (STD-CRM-8).
  9. Pagination becomes Previous, range and page, Next as 44px buttons, with Leads per page on its own line.
  10. Pre-sales keeps its queue card: follow-up status and next step replace stage and quality, and the action row is Log call, Log WA, then Decide when ready or Call otherwise.

Decisions for Shashi

  • WhatsApp button: open the chat directly (wa.me, number normalised with IDLM_Interakt::format_phone_for_interakt()), or open the Interakt inbox when Interakt is on, as the drawer does?
  • Should tapping WhatsApp or Call also log a touch for pre-sales, or stay a plain link? This mockup keeps them as plain links: no behaviour change.
  • Keep Previous/Next, or switch phones to "Show 25 more" using the existing cursor pagination?
